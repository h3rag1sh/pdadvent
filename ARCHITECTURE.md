# PlayDay: Новогодний Адвент — Архитектура

## Стек
- **Frontend:** React + Vite, React Router, Axios, CSS (custom properties, glow/animations)
- **Backend:** Node.js + Express, JWT auth, bcryptjs
- **БД:** SQLite (`server/data.sqlite`) — реляционная, с FK/unique constraints
- **Связь:** REST API `/api/*`, JWT Bearer token

## Модули
- `auth` — регистрация, вход, восстановление пароля (reset token), профиль `/me`
- `calendar/cases` — 31 день, просмотр кейса, предпросмотр дропа, открытие (серверный RNG)
- `inventory/claims` — инвентарь игрока, фильтры/сортировка
- `moderator` — терминал выдачи: поиск по коду/нику, смена статуса active→redeemed
- `admin` — CRUD календаря/предметов кейсов, настройка шансов, статистика открытий
- `superadmin` — управление ролями пользователей, настройка дат акции

## Роли и доступ (RBAC)
- `user` — календарь, открытие кейса текущего дня (в рамках дат акции), свой инвентарь/баланс
- `moderator` — всё user + терминал выдачи призов
- `admin` — всё moderator + управление контентом календаря/кейсов и статистика
- `superadmin` — всё admin + управление ролями и датами акции

## Механика открытия кейса (CS2 style)
1. Клиент запрашивает `POST /api/cases/:dayId/open`.
2. Сервер проверяет: авторизация, активность дня/акции, что сегодня соответствует `day_number` (или день доступен по датам акции), отсутствие `UserClaim(user_id, day_id)`.
3. Сервер выбирает выигрыш взвешенным рандомом по `drop_chance` **до** ответа клиенту.
4. В транзакции создаётся `UserClaim` (уникальный `claim_code`, status=`active`), при `reward_type=points` начисляется `bonus_balance`.
5. Сервер возвращает `{ claim, winningItem, reel }` — ленту для анимации с выигрышем в целевой позиции.
6. Клиент проигрывает горизонтальную рулетку и плавно останавливает на индикаторе; результат уже сохранён.
7. Повторное открытие того же дня запрещено (UNIQUE + проверка).

## Безопасность
- Пароли: `bcrypt` hash
- JWT, проверка роли на каждом защищённом роуте
- Никакой клиентской генерации результата; drop рассчитывается только на сервере
